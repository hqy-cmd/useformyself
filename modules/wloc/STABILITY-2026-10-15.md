# WLoc 稳定性与准确性复测

日期：2026-10-15。环境：macOS 27.0.1，Surge 6.10.0 (12300)。测试版本：7d753fe 中的协议实现；本机部署版本的主要差别为没有成功响应日志。

## 结论

本机短时测试中，HTTPS 改写、协议编码及两轮系统刷新均通过；Apple Maps 的 My Location 详情显示 1.29167° N、103.85000° E，与配置目标一致。仍不能据此保证长时间、所有应用或 iPhone 稳定生效。

## 测试结果

| 测试 | 结果 | 能证明的范围 |
| --- | --- | --- |
| 真实 HTTPS 合成 POST，两个目标域名各 30 次，4 并发 | 60/60 返回预期字节 | Surge TLS 与脚本处理链路 |
| 独立编码的随机、边界坐标与截断报文 | Node 768/768；Surge 引擎 768/768 | 编码、未知字段保留、异常放行 |
| 630016 字节、30000 个 Wi-Fi 项的超限响应 | Surge 约 23 ms，正确放行 | 本次超限输入没有造成脚本超时 |
| 两轮系统定位关闭/开启 | 每轮看到真实 locationd 请求，My Location 坐标均与目标一致 | 本机短时重复定位 |
| 停用模块并刷新定位 | 地图跟随当前位置时离开目标区域 | 恢复方向符合预期；没有记录原位置精确坐标 |
| 重新启用模块并刷新定位 | 再次出现 locationd POST，地图返回新加坡区域 | 恢复启用有效；此轮未读取精确坐标 |

HTTPS 请求耗时中位数 78.04 ms，p95 1654.96 ms，最大 1668.39 ms。包括 curl 进程、TLS 和调度成本，不能当作系统定位延迟。

768 个用例包括 512 个有效报文及 256 个截断报文，覆盖正负/零/极值坐标、不同高度和精度、1/2/20/100 个 Wi-Fi 项、未知 64 位字段保留以及指定字段删除。只使用虚构 BSSID。复现命令：`python3 tests/stress.py`，需要 Python、Node 和正在运行的本机 Surge；不会改变系统定位。

## 准确性的解释

地图坐标显示到小数点后五位，与目标显示值一致；这不是原始 Core Location 连续采样，也不是实测亚米误差。参数 hacc=10/vacc=10 是响应中声明的精度，不代表本次测量得到了 10 米误差。协议字节正确不等于系统一定采用它。

## 优化优先级

1. 优先完善诊断：区分无新请求、TLS 握手失败、脚本放行和成功响应但系统未采用。当前公开脚本已有成功响应字节数和放行原因日志，应先利用这些证据定位故障。
2. 缓存与刷新是体验瓶颈。全局定位开关会出现 Find My Mac 副作用提示，不应自动化为日常刷新方案；本次是在用户授权下临时测试。
3. 发布时可固定已验证脚本版本，避免远程 main 更新导致未验证的行为变化；本次没有更改模块下载地址或生产脚本。
4. 暂无证据支持改动编码算法或降低精度参数。超限报文表现正常，当前更值得投入持续观测与兼容性，而非微优化。
